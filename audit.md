## ⚠️ КРИТИЧЕСКИЕ НАХОДКИ — SECURITY

### 🔴 1. Секреты в git-истории

Файл `.env.local` закоммичен в git (не просто в `.gitignore` — он отслеживается):

```
.env.local содержит:
- VITE_BOT_TOKEN="873698…TuC4"   ← реальный токен бота
- VERCEL_OIDC_TOKEN="eyJhbG…PEDg" ← Vercel OIDC токен
- VITE_ADMIN_ID="1834686956"
```

`.env.local` присутствует в `git ls-files`. Даже если удалить сейчас, он останется в истории.

**Действие:** Немедленно отозвать токен бота через @BotFather, очистить историю git через `git filter-branch` или `bfg`.

### 🔴 2. Хардкод секретного ключа админа

`backend/api/deps.py`, строка 20:
```python
ADMIN_SECRET_KEY: str = os.getenv("ADMIN_SECRET_KEY", "f9XnzG1Ib0jYz4iZ8PoU518CcF43M1yEz1liGgUDYpA")
```

Хотя используется `os.getenv`, **значение по умолчанию — реальный ключ**. Если переменная окружения не задана (что случается при локальной разработке, забыли установить на Render, и т.д.), используется хардкод-ключ, который теперь лежит в открытом репозитории.

**Действие:** Убрать значение по умолчанию. Сделать обязательным: падать с ошибкой если не задан.

### 🔴 3. `/backup` — утечка БД через Telegram + shell injection

`backend/bot/handlers/common.py`, функция `cmd_backup`:

```python
command = f"PGPASSWORD={password} pg_dump -h {host} -p {port} -U {user} -d {database} > {backup_filename}"
result = subprocess.run(command, shell=True, ...)
```

**Три проблемы в одной:**
1. `shell=True` + неэкранированные параметры из `DATABASE_URL` = **shell injection** (если кто-то контролирует строку подключения)
2. Пароль передаётся в командной строке — виден в `ps aux` / `/proc`
3. **Полный дамп БД отправляется файлом в Telegram** — все имена клиентов, телефоны, записи уходят в чат

**Действие:** Убрать `/backup` команду полностью. Для бекапов использовать `pg_dump` только в CI или на сервере через cron, шифровать перед хранением.

---

### 🔴 4. WebSocket без аутентификации

`backend/api/websocket.py` — любой клиент может подключиться к `wss://.../ws` и получать все broadcast-сообщения (записи, отмены, изменения слотов). Никакой проверки нет.

**Действие:** Добавить проверку токена при подключении (query param), либо проверять `origin` заголовок, либо использовать Telegram initData для аутентификации.

---

### 🟠 5. Нет валидации ввода

`backend/api/routes/booking.py`:
- `client_name` — нет ограничения длины
- `phone` — никакой валидации формата (любая строка до 20 символов)
- `note` — текст без санитизации (но рендерится через aiogram HTML)

**Действие:** Добавить `Field(max_length=...)` в Pydantic модели. Валидировать телефон. Санитизировать HTML.

---

### 🟠 6. Phone в открытом виде

Телефоны клиентов хранятся в БД без шифрования. Для РФ это может быть нарушением 152-ФЗ «О персональных данных».

**Действие:** Минимум — замаскировать в логах. Для продакшна — шифровать поле phone или весь столбец БД.

### 8. `print()` в продакшене

Десятки `print()` в `admin.py`, `common.py` — в проде нужно использовать `logging`.

---

### 9. `asyncio.create_task` без обработки ошибок

В `booking.py`:
```python
asyncio.create_task(bot.send_message(chat_id=ADMIN_ID, ...))
```

Если уведомление упадёт — никто не узнает. Нет `.add_done_callback()` для логирования ошибки.

---

### 10. SessionLocal напрямую в хендлерах

Бот-хендлеры создают `SessionLocal()` напрямую через `with`, в то время как API использует FastAPI `Depends(get_db)`. Нет единой стратегии управления сессиями БД.

---

### 11. `scheduler.py` создаёт отдельный Bot инстанс

Вместо использования существующего `bot` из `bot.py`, создаётся новый `Bot(token=BOT_TOKEN, ...)`. Два инстанса бота с одним токеном — потенциальные гонки.

## 🟢 LOW — Рекомендации

### 12. SQLAlchemy relationship'ы не используются
Модели объявлены с `relationship()`, но везде в коде идут ручные запросы через `.filter()`. Лучше использовать `booking.slot` и т.д.

### 13. Mixed language
Комментарии и сообщения смешаны (русский + английский). Лучше выбрать один язык.

### 14. Нет тестов
Ни бэкенд, ни фронт не имеют ни одного теста.

### 15. `render.yaml` в двух местах
Есть `render.yaml` в корне и `backend/render.yaml`. Корневой — пустой/неактуальный?
